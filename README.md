# 柳比歇夫时间账本 · Lyubishchev Time Ledger

> 知乎黑客松 2026 参赛作品 ｜ 记录时间 → 统计去向 → AI 复盘 → Obsidian 闭环
>
> **线上 Demo（可直接体验）**：https://hannah8325.github.io/lyubishchev-tracker/

## 一、创作思路与目标用户

**这个产品始于一个很小的瞬间。**

作者某天晚上在 Obsidian 里写日记，一条消息弹进来——他下意识在日记里写下"我现在要看一下手机信息"，然后意识到：从七点洗漱到十点睡觉，自己的夜晚一直被回消息、甚至只是无意识地打开手机切碎，躺下时脑子还是乱的。而写下那句话的一刻，他第一次"看见"了时间是如何溜走的。

这恰是柳比歇夫时间统计法要解决的问题：**人对时间的主观感知和真实去向差距巨大**。柳比歇夫用 56 年坚持记录时间，一生完成 70 余部著作。但纸笔记录门槛太高，现有 App 又各有短板——于是有了这个产品：

**能不能把柳比歇夫工作法写成程序跑起来？手机电脑账号同步，提高对自己正在做的事的觉察，帮助事后反思；再做一个 Obsidian 插件，让「计划 → 实际时间 → 日记 → 总结复盘」形成完美闭环。**

**目标用户**（已在知乎验证需求，见第五节）：
- 感觉时间被手机切碎、想找回掌控感的知识工作者（"报复性熬夜""睡前无意识刷手机"是知乎高赞公共议题）；
- 尝试过柳比歇夫法 / aTimeLogger 但卡在"记录太麻烦、坚持不下来"的人；
- Obsidian 深度用户（日记 + 复盘人群，知乎上有大量高赞教程与插件生态）。

## 二、核心体验

整个产品只有一条主线，摩擦被压到最低：

```
悬浮窗输入"在做什么" → 回车自动计时 → 做完点结束 → 选一个时间类别 → 归档
                                         ↓
        今日时间轴（课程表式回看） ←  周/月分类饼图 + AI 复盘  →  导出 Obsidian / 插件双向同步
```

1. **悬浮窗计时（PC 工作流核心）**：桌面常驻小窗，输入即计时、可拖动可最小化，不打断当前工作。正式版将基于 Electron/Tauri 实现置顶与开机自启。
2. **先记录、后归类**：结束时才选类别——记录动作本身零思考成本，类别用于事后统计与复盘，能看清"我具体做了什么"，而不只是"我在工作"。
3. **今日时间轴**：一天像课程表一样展开（5:00–次日 3:00），每个色块带事件名、起止时间和时长，红色竖线标记"现在"。
4. **周/月统计优化**：分类饼图（悬停看详情）+ 时长排行 + 环比洞察（深度工作较上周变化、睡眠均值、优化建议）。
5. **AI 复盘教练**：基于统计数据生成「概况 / 亮点 / 时间黑洞 / 下周建议」，支持多轮追问（接入 Moonshot 大模型；未配置 Key 时自动降级为本地规则版）。
6. **自然语言补录**："下午3点到4点开会""昨晚读书2小时""刚才"——一句话解析成结构化记录，解决忘记记录的最大痛点。
7. **Obsidian 插件（双向同步）**：导出 `.time.json` → 插件读取生成周/月饼图；插件内改类别名/颜色写回 `sync.time.json` → 网页版导入，完成闭环；一键把今日时间日志写入日记。

## 三、技术方案

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 Demo | 单文件 HTML5（原生 JS + Canvas） | 零构建、零依赖，GitHub Pages 直接托管；localStorage 持久化，刷新不丢计时状态 |
| 桌面端（规划） | Electron / Tauri | 开机自启、悬浮窗置顶、全局快捷键 |
| AI 能力 | Moonshot API（可切换知乎直答） | 自然语言时间解析（结构化抽取）、复盘报告生成、多轮追问；带本地规则降级 |
| Obsidian 插件 | 纯 JavaScript（Obsidian API，免构建） | `manifest.json + main.js`，读取导出文件合并统计，编辑回写同步文件 |
| 账号与云同步（规划） | BaaS（Supabase） | 邮箱/知乎 OAuth 登录，PC/手机/网页三端同步，无自购硬件 |

**数据结构**：`类别 categories（id/名称/颜色）` + `记录 records（事件名/类别/开始/结束）`，一切统计按类别归集；导出为 Markdown（人读）与 JSON（机器读/插件读）双格式。

## 四、使用的知乎开放能力

1. **知乎 OAuth（规划中，已留接入位）**：知乎账号一键登录，登录数据计入人气奖评审；创建项目后使用活动页分配的 app_id / app_key。
2. **知乎搜索 / 知乎直答（AI 复盘双引擎）**：用户追问"我为什么总是睡前刷手机"时，AI 结合**个人时间数据**与**知乎社区高赞洞察**（如"报复性熬夜"心理学分析、时间管理方法论）生成针对性建议——"个人数据 × 社区智慧"是本地单机 App 无法实现的体验。
3. **社区内容回流**：周复盘一键生成图文（饼图 + 变化 + 感悟），可发布为知乎文章/回答，为"时间管理""自律"话题供给真实数据型内容。

## 五、与知乎社区生态的契合点

- **痛点是知乎高赞公共议题**：「总在睡前报复性熬夜，人们究竟在报复什么」下有多个 16–37 赞心理学高赞回答（[问题链接](https://www.zhihu.com/question/15224318473)）——"无意识刷手机到两三点"有海量共鸣者，但现有答案只给解释不给工具，本产品把"觉察"工程化。
- **方法有社区认知基础**：柳比歇夫时间统计法在知乎被反复推荐（[创业者时间管理实践](https://zhuanlan.zhihu.com/p/2079594317795031024)称其为"解决自我感动式忙碌、看不清时间黑洞"的方法，落地建议"每晚极简复盘、每周统计结构占比"正是本产品自动完成的），同时社区存在对现有工具"记录摩擦大、过度折腾"的普遍抱怨（[工具篇](https://zhuanlan.zhihu.com/p/698443801)、[《时光长廊》体验](https://zhuanlan.zhihu.com/p/2081413032324944784)——"步骤不多，但就是这几步，很多时候就懒得写了"）。
- **种子用户即知乎原生人群**：Obsidian 在知乎是高热度生态（[113 赞新手完全指南](https://zhuanlan.zhihu.com/p/2010454474213323602)、[21 赞晨间日记复盘自动化](https://zhuanlan.zhihu.com/p/1961141466731619077)），"日记 + 复盘"人群与本产品 Obsidian 插件的目标用户高度重合。
- **知乎是天然的冷启动渠道**：时间统计法相关问题（[怎样评价柳比歇夫的时间统计法](https://www.zhihu.com/question/27433886)）下持续有用户寻求更好工具，插件发布与真实使用记录可直接转化为社区内容。

## 六、对社区用户的实际价值

1. **给"想改变但不知从何改起"的人一面镜子**：饼图让时间黑洞显形，优化建议给出可执行的下一步。
2. **大幅降低柳比歇夫法的坚持门槛**：悬浮窗 + 先记后分 + 自然语言补录，把记录成本压到一句话。
3. **打通 Obsidian 复盘闭环**：时间数据自动进入日记与知识库，与 Obsidian 用户的既有工作流无缝衔接。
4. **沉淀真实经验到社区**：用户的周复盘内容回流知乎，形成"工具 → 实践 → 分享 → 吸引更多实践者"的正循环。
